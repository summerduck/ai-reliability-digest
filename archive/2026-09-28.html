Evaluating Real-Time Voice Agents: From Component Quality to Grounded Outcomes

This survey of 38 sources argues that voice-agent evaluation has fragmented across speech modeling, turn-taking psycholinguistics, and agentic benchmarking, with no single metric capturing whether a deployed system is actually good. It documents a shift from component-quality metrics (latency, WER) toward grounded-outcome verification that checks actual backend state changes.

Why it matters
This is a direct blueprint for building eval strategy on a real-time conversational AI team — cite the shift from transcript-trusting to state-verifying evaluation as the standard you'd push for in ASR/TTS pipeline testing.

04 · arXiv cs.AI · 25 min read

Inquesto Score: A reliability Protocol For Voice Agents

Inquesto Score defines voice-agent reliability as the percentage of calls achieving the caller's goal without a functional failure, using explicit failure severity levels, audio-measured timing failures (talk-over, delayed response), and a pinned open-model judge for semantic failures. The protocol was validated on 306 calls across 13 configurations, three acoustic conditions, and four speaker groups.

Why it matters
This is a concrete, reusable reliability metric and test harness design for exactly the ASR/TTS conversational systems this role targets — worth studying its failure taxonomy as a template for your own test suites.

05 · NVIDIA Technical Blog · 10 min read

How SWE-Serve Exposes the Gap Between Local Tests and Live Serving

SWE-Serve shows that a coding agent's patch to inference-serving software can pass local unit tests yet fail once the server loads a real model and handles live requests, exposing a systemic gap between local and production test environments. The piece frames this as a benchmark specifically for evaluating changes to serving infrastructure under realistic load.

Why it matters
This is the clearest articulation this week of why testing non-deterministic, distributed LLM-serving systems requires more than unit tests — a strong example to cite when discussing CI/CD gates for production inference stacks.
