Tool-Calling LLM Agents Under Realistic MCP Faults: Scale Does Not Purchase Fault Tolerance

Researchers built MCP-Injector, a protocol-aware fault-injection middleware for the Model Context Protocol, calibrated against 57,240 real GitHub issues across 1,774 MCP repos. Across 1,350 experimental cells spanning two model sizes and three agent stacks, realistic tool failures (permanent, transient, intermittent) cut task-completion scores by 60%, and a larger 120B model showed no better resilience than a 20B one.

Why it matters
This is essentially a blueprint for chaos-engineering LLM agents: a reusable fault-injection layer with a calibrated, real-world failure distribution is exactly the kind of test harness you'd want to build or reference when arguing for fault-tolerance testing in a conversational AI pipeline that depends on external tools, ASR/TTS services, or retrieval APIs.

02 · arXiv cs.AI · 20 min read

Trial by Trace: Benchmarking AI Agent Harnesses for Reliability and Failure Attribution

TraceTrial-Bench decomposes agent harness reliability into seven components (context, execution, governance, lifecycle, observability, tools, verification) and runs 95 mechanism-level tasks across 4 harnesses and 9 models, totaling 3,420 traced runs. The study finds that 31.1% of runs succeed at the task level despite violating at least one harness reliability criterion, showing task success alone hides real reliability gaps.

Why it matters
The seven-component taxonomy and the finding that 'passing' runs can still fail reliability checks is a ready-made framework for designing regression test suites and observability dashboards for agentic systems — directly applicable to building eval gates beyond simple pass/fail metrics.

How Numan Built an Eval-First AI Health Coach with LangGraph and LangSmith

Numan describes building 'Nu', a health coaching agent, with per-category evals, simulated multi-turn conversations, and hard safety gates around a regulatory boundary, all wired into LangGraph and LangSmith. The eval suite runs continuously against production traffic patterns rather than being a one-time pre-launch check.

Why it matters
This is a concrete, production-grade case study of 'eval-first' development for a conversational agent in a regulated domain — a strong template and talking point for interviews about how you'd design regression testing and safety gates for a real-time LLM product.

04 · arXiv cs.AI · 18 min read

Reproducible Evaluation as the Substrate for Safe Prompt Compression in Production Agents

The authors build an offline evaluation harness for a production conversational agent that stays reproducible even as the live backend data it operates on changes, and can be regenerated on demand when it goes stale. Using this harness as a fitness function for GEPA-based prompt optimization under a correctness gate, they shrink prompt size by 3.5-7.6% across three model families without regressing correctness, sometimes improving it.

Why it matters
This directly tackles a core pain point in LLM testing — benchmark drift against live, mutable data — and shows how a correctness gate can guard automated prompt optimization against reward hacking, a pattern worth citing when discussing regression testing for prompts in production.

Designing an AI serving harness built to last

The piece argues that enterprise AI's competitive edge is shifting from model selection to the serving infrastructure built around models — the harness that handles routing, fallback, observability, and governance. It frames model-agnostic harness design as the more durable investment compared to chasing the latest frontier model.

Why it matters

06 · arXiv cs.AI · 30 min read

Permission to Retry: A Study of Authorization and Recovery in AI Agent Workflows

This study isolates execution-time recovery decisions (checkpointing, permission to dispatch, evidence of external effects, permission to reconcile) from language-model behavior, running 336 histories across LangGraph and Temporal hosts and 14 schedules. Retained-ledger reconciliation passes all 42 histories per host, while cached retry, revalidation, and stable-key retry strategies show more variable pass rates.

Why it matters
This formalizes retry/recovery semantics for agentic workflows in a way directly transferable to testing distributed, non-deterministic conversational pipelines — a good reference for designing idempotency and retry tests against flaky tool or API calls.

Trends this week

Harness reliability is now a first-class, separately-measured research object
Trial by Trace, When Agents Fail, MCP-Injector, Async-RBench, and SWE-Shift all explicitly decouple harness/execution-layer failures from model capability, each introducing dedicated taxonomies, fault injectors, or attribution frameworks this single week.

Production teams are operationalizing 'eval-first' and continuous regression testing for agents
Numan's eval-first health coach, LangChain's new LangSmith Gateway runtime controls, and the GEPA-based reproducible-evaluation-under-prompt-compression paper all describe live, continuously-run eval pipelines rather than one-off pre-launch tests.

Safety and correctness do not survive the transition from base model to deployed agent harness
BARC-Bench, the AI-for-Science agent safety study, and the MCP fault-tolerance paper all show that wrapping a model in a harness/agent loop — even without adversarial intent — degrades safety or reliability guarantees that held for the base model alone.
