Harness or Model? Isolating the Harness Effect in Agentic Coding with a Contamination-Controlled Private Suite

Researchers ran paired same-model contrasts across 800 planned runs on a private, contamination-controlled 256-task suite to isolate the effect of the harness (tools, prompts, control flow) from the underlying model. Neither vendor-native harness showed a reliable average advantage over a neutral alternative, but the aggregate masked opposite effects by task type (repository vs. contest tasks), and 22 of 81 wall-clock-cancelled runs had actually produced a passing patch.

Why it matters
This is a direct blueprint for test design in agentic system evaluation: build paired, contamination-controlled suites, stratify by task type before trusting an average, and treat wall-clock cutoffs as a source of false negatives in your test harness — all concrete points to raise when discussing regression testing for agent pipelines.

02 · arXiv cs.AI · 25 min read

Measurement Without Validity: The Compounding Reliability Problem in Agentic AI Evaluation

The paper formalizes a three-layer validity model (task generation, human-simulator calibration, automated judgment) showing validity multiplies rather than adds across stages, so a pipeline with 70% validity per stage may only be 34% valid overall. A survey of 55 published agentic eval papers found ~82% use structurally mismatched or absent inter-rater reliability metrics, plus concrete task-validity flaws in 7 of 10 popular benchmarks.

Why it matters
This gives a rigorous vocabulary and citable framework for arguing, in interviews or design docs, why 'the eval passed' isn't the same as 'the system is reliable' — essential ammunition for an AI reliability role pushing back on shallow LLM-as-judge pipelines.

An update on recent Claude Code quality reports

Anthropic traced user reports of degraded Claude behavior to three separate, unrelated changes: a reasoning-effort default change, a context-clearing bug that fired every turn instead of once, and a third issue affecting Claude Code, the Agent SDK, and Cowork specifically (not the API). All three were identified and fixed by April 20.

Why it matters
A rare public root-cause postmortem on a production LLM regression — exactly the kind of failure-analysis narrative (multiple confounded changes, silent degradation, scoped impact) you'd want to reference when discussing how to detect and triage non-deterministic system regressions.

Agent Evaluation Metric for multi-turn conversations

AWS introduces AEM, a decomposable turn-level correctness metric for multi-turn agents that pinpoints the exact turn where a failure originated versus turns that merely inherited it. This addresses a known gap where single-turn evals miss cascading failures common in conversational agents.

Why it matters
Directly applicable to testing conversational AI/ASR-TTS pipelines: turn-level failure attribution is exactly the kind of test harness feature needed for debugging multi-turn regressions rather than just pass/fail scoring.

06 · arXiv cs.AI · 20 min read

Can We Trust LLM Judges: A Study of Capability-Dependent Biases and Multi-Judge Ensemble for Bias Calibration

Across 36 judge-examinee pairs, the study finds task accuracy strongly predicts judging accuracy but more capable examinee models still receive systematically more lenient scores from every judge. The authors propose calibrated weighted majority voting across judges, using disagreement-based error-rate estimates with no ground truth needed, which tracks an oracle ensemble within 0.5 points.

Why it matters
A practical recipe for building more trustworthy LLM-as-judge pipelines in regression testing — using weighted multi-judge ensembles instead of a single judge is a concrete technique to propose when building eval infrastructure for a conversational AI team.

Trends this week

Evaluation validity is the industry's central unsolved problem
Measurement Without Validity's multiplicative validity-collapse model, K-Bench showing unlearning benchmarks miss leaks in agent tool/CoT channels, the Praxa audit finding metrics that measure the wrong construct, and WorkflowPerturb testing whether workflow metrics are even calibrated all converge on the same finding: passing scores frequently don't mean what practitioners assume.

Harness design now rivals model choice in determining agent performance
The Harness or Model? paper finds no reliable average harness advantage but large task-type-dependent swings; Anthropic's Claude Code postmortem traces user-visible quality drops to harness-layer changes (reasoning effort defaults, context-clearing bugs) rather than the underlying model; Managed Agents and the Agents API both reflect vendors racing to productize harness abstractions.

Multi-turn and multi-channel evaluation is replacing single-shot scoring
AWS's Agent Evaluation Metric attributes failures to the originating turn in multi-turn conversations; K-Bench inspects six separate channels (CoT, tool calls, observations, final answer) rather than just the answer; the Agent Incident Registry catalogs failure mechanisms across the full agent action surface.
